# 欠费查询模块

本模块包含所有与欠费查询相关的功能和处理流程。

## 可用命令

| 功能 | 命令 |
|------|------|
| 通过名称查询欠费总额（推荐） | `python3 {baseDir}/scripts/main.py get_arrears <收费系统名称> <小区名称>` |
| 通过名称查询本年度物业费欠费 | `python3 {baseDir}/scripts/main.py get_current_year_arrears <收费系统名称> <小区名称>` |
| 通过名称查询自定义时间范围欠费 | `python3 {baseDir}/scripts/main.py get_custom_range_arrears <收费系统名称> <小区名称> <开始日期> <结束日期>` |
| 查询小区欠费户数统计 | `python3 {baseDir}/scripts/main.py get_arrear_households <收费系统名称> <小区名称>` |
| 查询房屋/楼栋/单元欠费总额 | `python3 {baseDir}/scripts/main.py get_household_arrears <收费系统名称> <小区名称> <关键词>` |
| 通过小区ID查询欠费总额（旧版） | `python3 {baseDir}/scripts/main.py get_community_total_arrears <小区ID>` |
| 通过小区ID查询本年度物业费欠费 | `python3 {baseDir}/scripts/main.py get_community_current_year_arrears <小区ID>` |
| 通过小区ID查询自定义时间范围欠费 | `python3 {baseDir}/scripts/main.py get_community_custom_range_arrears <小区ID> <开始时间戳> <结束时间戳>` |

---

## 自定义时间范围查询说明

当用户查询自定义时间范围的欠费时：

1. **AI（你）负责理解用户输入的时间**，将其转换成标准的 YYYY-MM-DD 格式
2. 用户的时间表述可以是任意格式，例如：
   - "2025年1月到2026年12月"
   - "去年到今年"
   - "25年1月到今年2月"
   - "2025/12/1-2026/3/1"
   - "本月"、"上月"、"去年"
3. 你需要把开始和结束日期都转成 YYYY-MM-DD 格式后再调用命令
4. 结束时间会自动设置为当天的 23:59:59

## 分情况处理流程

### 情况 1：用户提供了完整信息查询总欠费
**用户示例**："查询波波测试收费系统里碧桂园小区的欠费"

**处理步骤**：
1. 直接调用 `get_arrears <收费系统名称> <小区名称>`
2. 展示结果给用户

---

### 情况 2：用户查询本年度物业费欠费
**用户示例**："查询波波测试收费系统里碧桂园小区今年的物业费欠费" 或 "查询某小区本年度物业费欠费"

**处理步骤**：
1. 确认用户是要查询"本年度物业费欠费"
2. 如果信息完整，直接调用 `get_current_year_arrears <收费系统名称> <小区名称>`
3. 如果信息不完整，按照下面的情况逐步询问用户
4. 展示结果给用户

---

### 情况 3：用户查询自定义时间范围欠费
**用户示例**："查询波波测试收费系统里碧桂园小区2025年1月到2026年12月的物业费欠费"、"查某小区去年到今年的欠费"、"查询25年1月到今年2月的欠费"

**处理步骤**：
1. 确认用户是要查询自定义时间范围的欠费
2. 提取用户提到的日期范围信息
3. 如果信息完整（收费系统名称、小区名称、日期范围都有），直接调用 `get_custom_range_arrears <收费系统名称> <小区名称> <日期范围>`
4. 如果信息不完整，逐步询问用户缺失的信息
5. 展示结果给用户

---

### 情况 4：用户只提供了小区名
**用户示例**："查询碧桂园小区的欠费" 或 "查询碧桂园小区本年度物业费欠费"

**处理步骤**：
1. 先调用 `list_charge_systems` 获取所有可用的收费系统
2. **如果只有一个收费系统**：直接使用，不展示也不询问用户
3. **如果有多个收费系统**：展示给用户选择
4. 使用收费系统后，调用 `search_community <收费系统名称> <小区名>` 确认小区
5. **如果只有一个匹配小区**：直接使用
6. **如果有多个匹配小区**：展示给用户选择
7. 根据用户需求调用相应命令并展示结果

---

### 情况 5：用户查询非常模糊
**用户示例**："查询当前小区欠费"、"查欠费"、"查今年的物业费"、"查小区收费情况"

**处理步骤**：
1. 先调用 `list_charge_systems` 获取所有可用的收费系统
2. **如果只有一个收费系统**：直接使用，不展示也不询问用户
3. **如果有多个收费系统**：展示给用户选择
4. 使用收费系统后，调用 `search_community <收费系统名称> ""` 获取该收费系统下的所有小区
5. **如果只有一个小区**：直接使用，不展示也不询问用户
6. **如果有多个小区**：询问用户："请问您想查询哪个小区？"
7. 用户选择小区后，根据用户需求调用相应命令
8. 展示结果给用户（可在结果开头简要说明查询的是哪个收费系统下的哪个小区）

---

### 情况 6：有多个匹配的小区
**用户示例**："查询波波系统里带有'花园'的小区欠费"

**处理步骤**：
1. 调用 `search_community <收费系统名称> <小区关键词>` 获取匹配的小区
2. **如果只有一个匹配小区**：直接使用，不展示也不询问用户
3. **如果有多个匹配小区**：展示给用户选择，询问："找到多个匹配小区，请您选择一下："
4. 用户选择后，根据用户需求调用相应命令
5. 展示结果给用户

---

### 情况 10：用户查询欠费户数统计
**用户示例**：
- "截至当前小区欠费总户数是多少？"
- "小区有多少户欠费？"
- "小区欠费户数统计"

**处理步骤**：
1. 只要用户询问关于"欠费户数"、"欠费总户数"的任何统计，都直接调用 `get_arrear_households` 命令获取完整的欠费户数统计
2. 如果信息完整（收费系统名称、小区名称都有），直接调用 `get_arrear_households <收费系统名称> <小区名称>`
3. 如果信息不完整，按照前面的情况逐步询问用户缺失的信息
4. 展示完整的统计结果给用户（结果中包含用户需要的所有信息）

---

### 情况 11：用户查询房屋/楼栋/单元欠费

**用户示例**：
- "查询碧桂园小区1栋的欠费"
- "查一下3单元欠了多少钱"
- "101室欠费多少"
- "查A栋的欠费"

**处理步骤**：
1. 先确认小区信息（如不完整，按现有逻辑询问）
2. 调用 `get_household_arrears <收费系统名称> <小区名称> <用户的查询关键词>`
3. 如果返回 `MULTI_MATCH:` 开头的多个匹配项，列出给用户选择，并提示用户可以通过以下方式选择：
   - 输入序号（如 "1"、"2"）
   - 输入中文序号（如 "一"、"二"）
   - 输入文字描述（如 "第一个"、"第二个"、"最后一个"）
   - 输入完整路径（如 "1栋/1单元/103"）
4. 用户做出选择后，将用户的选择作为新的关键词再次调用 `get_household_arrears <收费系统名称> <小区名称> <用户的选择>`
5. 展示最终欠费总额给用户

**匹配规则说明**：
- 模糊匹配会自动找出所有名称包含关键词的楼栋/单元/房屋
- 如果多个匹配项有层级关系（如同时匹配到"1栋"和"1栋A座"），会自动选择最高层级的"1栋"
- 如果多个匹配项之间没有层级关系（如同时匹配到"1栋"和"2栋"），会列出供用户选择
- 当用户输入包含 "/" 时，会优先进行精确路径匹配
- 系统会记住上一次的匹配列表（5分钟内有效），支持用户通过多种方式选择

---

### 处理候选列表（CANDIDATES: 格式）

当查询房屋（欠费查询、抄表、查询读数）找不到精确匹配时，系统会返回候选列表格式：

```
CANDIDATES:
用户查询: <用户原始关键词>
候选列表:
1. 1栋/1单元/101
2. 1栋/1单元/102
3. 1栋/1单元/103
...
提示: 未找到精确匹配，请从以上候选中选择，或使用完整路径如"1栋/1单元/103"
```

**处理步骤**：
1. 首先仔细阅读候选列表和用户的原始查询
2. 尝试智能判断哪个候选最符合用户输入（例如用户说"一栋一单元103"，候选中有"1栋/1单元/103"就是最匹配的）
3. 如果非常确定某个候选是正确的，直接使用该候选重新调用命令，无需询问用户
4. 如果不确定，展示候选列表给用户，并请用户选择
5. 支持用户通过以下方式选择：
   - 输入序号（如 "1"、"2"）
   - 输入完整路径（如 "1栋/1单元/103"）

**中文数字支持**：
- 用户可能使用中文数字输入（如"一栋一单元103"），系统会自动转换为阿拉伯数字进行匹配
- 当看到用户使用中文数字时，优先选择对应阿拉伯数字的候选
