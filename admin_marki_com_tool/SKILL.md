# Admin Marki Tool

这个工具可以让 AI 通过 HTTP 接口访问**马克智慧物业系统**，支持查询物业数据和执行操作。

## 安装依赖

在使用前，请确保安装了所需的依赖包：
```bash
pip install -r {baseDir}/requirements.txt
```

## 功能模块

本技能采用模块化设计，根据查询类型读取对应模块文档：

| 模块 | 功能 | 文件位置 |
|------|------|----------|
| [欠费查询](./references/arrears.md) | 小区欠费总额、本年度物业费欠费、自定义范围欠费、楼栋/单元/房屋欠费、欠费户数统计 | `{baseDir}/references/arrears.md` |
| [报表数据](./references/reports.md) | 今日收入统计、自定义范围收入统计、本月支出统计、本月收缴率统计 | `{baseDir}/references/reports.md` |
| [抄表](./references/meter.md) | 水表/电表抄表、查询当前读数 | `{baseDir}/references/meter.md` |
| [催费](./references/reminder.md) | *(预留)* 短信催缴、微信催费、生成催缴通知单等 | `{baseDir}/references/reminder.md` |
| [收款](./references/collection.md) | *(预留)* 收费收款、优惠减免、预存款充值等 | `{baseDir}/references/collection.md` |

**使用规则**：
- 根据用户问题的类型，读取对应的模块文件获取详细处理流程
- 多个模块涉及的通用规则（如登录处理、房屋匹配）请参见下文

## 核心原则（所有模块通用）

- **对用户只展示名称，不展示 ID**
- **静默选择原则**：当只有一个选项时，直接使用，不展示也不询问用户。
- **根据信息完整程度处理**：信息不完整时，先获取选项，只有多个选项时才询问用户
- **记住用户选择**：同一对话中，记住用户上次使用的收费系统和小区，优先使用
- **返回结果时**：需要告知用户静默使用了哪个选项（收费系统/小区/房屋）
- **智能匹配**：找不到精确匹配时，先尝试智能判断，不确定时再列出候选让用户选择
- **告知用户**：智能判断选择的选项必须要告知用户
- **严格输出约束（防止幻觉）**：
  - **只输出脚本实际返回的内容**，禁止编造脚本未返回的数据和内容
  - 必须校验用户询问的内容跟这个skill支持的功能是否一致
  - 如果脚本只返回欠费总额，即使用户明确询问某类费用（如物业费），也不能编造该类费用的具体金额
  - 如果接口不支持按费用类型过滤，必须如实告知用户"当前系统只支持查询全部收费项目的欠费总额，无法单独区分X费欠费"
  - 禁止添加脚本输出中没有的猜测性描述（如"该房屋当前只有物业费欠费"）
  - 所有结论和数据都必须有脚本输出作为依据，不能自行推断补充

## 对话风格规范

- **禁止使用**暴露内部处理流程的话术（如"根据SKILL.md要求..."、"让我先列出收费系统..."）
- **推荐使用**简洁专业的表达："好的，我来帮您查询..."、"请问您想查询哪个小区？"
- **整体语气**：专业、简洁、高效，符合物业管理人员的日常工作习惯
- **回复原则**：直接执行操作，静默使用单一选项，只在必要时询问用户

## 登录提示处理（通用）

当运行任何命令后，如果输出包含 `AUTH_REQUIRED` 标记，表示用户需要先登录。按以下格式处理：

1. 提取 `LOGIN_URL:` 后的完整登录链接
2. 提取 `MESSAGE:` 后的提示消息
3. 按以下格式展示：

```
{MESSAGE内容}

🔗 登录链接：{LOGIN_URL内容}

登录成功后，请再次询问我即可继续查询。
```

**重要**：不要展示 `http://localhost:8080/callback` 这样的本地回调链接，只展示用户需要点击的登录链接。

## 房屋匹配规则（所有模块通用）

当查询房屋、楼栋、单元时，遵循以下规则：

1. **模糊匹配**：自动找出所有名称包含关键词的楼栋/单元/房屋
2. **层级优先**：如果多个匹配项有层级关系（如同时匹配到"1栋"和"1栋A座"），自动选择最高层级
3. **多候选处理**：如果多个匹配项之间没有层级关系，列出供用户选择
4. **精确路径匹配**：当用户输入包含 "/" 时（如"1栋/1单元/101"），优先进行精确路径匹配
5. **匹配缓存**：系统会记住上一次的匹配列表（5分钟内有效）
6. **候选列表处理**：当返回 `CANDIDATES:` 格式的候选列表时：
   - 首先尝试智能判断哪个候选最符合用户输入
   - 如果确定，直接使用该候选重新调用命令
   - 如果不确定，展示候选列表让用户选择
   - 支持序号选择（阿拉伯/中文数字）和完整路径选择
7. **中文数字支持**：用户输入中文数字（如"一栋一单元"），优先匹配对应阿拉伯数字的候选
8. **精确路径自动选择**：当用户输入包含完整的路径分隔符"/"（如"1栋/1单元/101"）并且搜索返回多个候选时：
   - AI直接根据用户输入判断哪个候选是最佳匹配
   - **不需要**再列出候选询问用户
   - 选择原则：用户输入的完整路径与哪个候选最一致就选哪个
   - 只有当多个候选看起来都很匹配、无法确定时才询问用户

## 内部辅助命令（仅 AI 使用）

这些命令用于获取名称到 ID 的映射，**不要直接展示给用户**：

- `_get_charge_system_map` - 获取 `{收费系统名称: 收费系统ID}` 的 JSON 映射
- `_get_community_map <收费系统ID> <小区关键词>` - 获取 `{小区名称: 小区ID}` 的 JSON 映射
